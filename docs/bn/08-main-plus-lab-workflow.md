# Main + Lab ওয়ার্কফ্লো — মালিকের সৃজনশীল কাজের নিয়ম

মালিকের কাজের ধরন: **একটা main ফাইলই সত্য; বাকি সব পরীক্ষার জায়গা।**
এই নিয়ম ভাঙলে পুরো সিস্টেম এলোমেলো হয়ে যায়।

## মূলনীতি

1. প্রতিটা ভিডিওর একটা (বড়জোর কয়েকটা part-এর) **main ফাইল** থাকে।
   চূড়ান্ত সবকিছু শেষমেশ ওখানেই জমা হয়।
2. নতুন আইডিয়া প্রথমে **lab ফাইলে** জন্মায় (`test_*`, `*_demo`, `*_variants`,
   বা আলাদা ছোট scene)। Lab-এ ভুল করা যায়, main-এ নয়।
3. মালিকের মাথায় আইডিয়া না এলে AI **নিজের মতো করে** lab-এ একটা প্রস্তাব
   বানাবে—সেটা দেখে মালিক আইডিয়া বের করবেন, পছন্দ/মিশ্রণ/বাতিল করবেন।
4. কোনো অংশ চূড়ান্ত হলেই তবে সেটা main-এ **promote** হয়। Promote করা মানে
   কপি-পেস্ট নয়—main-এর প্যাটার্ন (builder/segment/body) অনুযায়ী বসানো।
5. Partial render, log, temp—সব **cache**-এ। Final শুধু `videos/`/`output/`-এ
   (এবং প্রকাশের সময় GitHub Release-এ)।

## ধাপে ধাপে

### ১) শুরুতে মানচিত্র
কাজ ধরার আগে বের করো: main ফাইল কোনটা, main class কোনটা, কোন প্যাটার্ন
(দেখো `07-code-anatomy.md`)। Main না থাকলে বানানোর আগে মালিককে জানাও।

### ২) Lab-এ পরীক্ষা
- আলাদা ফাইলে ছোট scene বানাও; নামে যেন বোঝা যায় এটা lab।
- কম মানে (`-ql`) render করে মালিককে দেখাও। একাধিক variant থাকলে সব দেখাও।
- এই ধাপে main ফাইলে হাত দেওয়া নিষেধ।

### ৩) সিদ্ধান্ত লিখে রাখা
মালিক যা পছন্দ/বাতিল করলেন, `DECISIONS.md`-তে এক লাইনে কারণসহ লিখে রাখো।
বাতিল variant মুছে ফেলবে না—সিদ্ধান্তের প্রমাণ হিসেবে lab-এই থাকুক
(মালিক না বললে)।

### ৪) Promote (main-এ তোলা)
নিচের checklist ধরে এগোও:

- [ ] কোন lab ফাইল/class থেকে আসছে?
- [ ] Main-এর প্যাটার্ন অনুযায়ী কোথায় বসবে?
  (Pattern A হলে builder + construct-এর কোন জায়গায়; B হলে কোন segment;
  C হলে কোন body/ডেটা)
- [ ] নতুন `self.*` state বা asset লাগছে কি?
- [ ] কপি হওয়া helper আনছ কি? আনলে নোটে লিখে রাখো (পরে shared করার প্রার্থী)।
- [ ] Voice/timing-এ প্রভাব পড়ছে কি? পড়লে voice-to-manim skill-এর
  manifest পথে যাও—হাতে `wait` বাড়িয়ে মেলানোর চেষ্টা কোরো না।

### ৫) যাচাই
- শুধু প্রভাবিত অংশ draft render করো; frame দেখে মিলাও আগের সাথে।
- ভুল হলে শুধু ওই অংশ ঠিক করো। কিন্তু ভুলটা যদি shared helper/engine-এ হয়,
  কেন্দ্রে ঠিক করে প্রভাবিত সব অংশ আবার render করো।

### ৬) শেষকাজ
- `PROGRESS.md` আপডেট: কী হলো, কী বাকি, পরের ধাপে কার অনুমতি লাগবে।
- কাঠামো বদলে থাকলে project-এর `CODE_ANATOMY` আপডেট।
- Final ভিডিও Git-এ নয়—Release-এ।
